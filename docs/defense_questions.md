# Вопросы к защите: краткие опорные ответы

1. **HTTP/1.0 и HTTP/1.1.** В HTTP/1.1 соединения по умолчанию могут переиспользоваться; обязателен Host. В HTTP/1.0 соединение обычно закрывается после ответа.
2. **Content-Length.** Длина тела в байтах. По ней принимающая сторона знает, сколько байтов читать.
3. **Chunked.** Тело разбито на чанки: шестнадцатеричный размер, CRLF, данные; завершается нулевым чанком.
4. **GET и POST.** GET обычно получает представление ресурса; POST передаёт данные для обработки. Семантика определяется HTTP, а не TCP.
5. **Keep-alive.** Несколько HTTP-обменов по одному TCP-соединению при согласованном framing.
6. **301/302/307.** Перенаправления; 307 сохраняет метод и тело. Поведение клиента зависит от кода.
7. **HEAD.** Сервер возвращает заголовки, соответствующие GET, но не тело.
8. **Content-Type.** Указывает тип представления; charset задаёт кодировку текста.
9. **listen/backlog.** listen переводит сокет в режим ожидания соединений; backlog задаёт очередь ожидающих подключений.
10. **accept/connect.** accept принимает входящее соединение сервера; connect инициирует соединение клиента.
11. **recv.** Может вернуть меньше байтов, чем запрошено. TCP является потоком, поэтому приложение само определяет границы HTTP-сообщения.
12. **SIGPIPE.** Ошибка записи в закрытое соединение; в Python обычно проявляется как OSError/BrokenPipeError.
13. **close/shutdown.** shutdown управляет направлением обмена; close освобождает дескриптор.
14. **SO_REUSEADDR.** Позволяет повторно использовать локальный адрес в типичных сценариях перезапуска сервера.
15. **Контекстный менеджер.** Гарантирует закрытие ресурса при выходе из блока, в том числе при исключении.
16. **Callable в Router.** Позволяет хранить вызываемый обработчик, не выполняя поиск по строковому имени.
17. **Исключения в __exit__.** Здесь закрытие не подавляет исходное исключение: возвращается False.
18. **dataclass.** Автоматически создаёт типичные методы хранения данных и делает модели компактнее.
19. **isinstance.** Проверка типа иногда нужна на границах ввода; часто лучше использовать полиморфизм и протоколы.
20. **Lock.** Защищает совместно используемое состояние от одновременной модификации.
21. **Tkinter из фонового потока.** Это небезопасно; обновление виджетов выполняется главным потоком.
22. **root.after.** Планирует обработчик в главном цикле событий.
23. **queue.Queue.** Потокобезопасная очередь для передачи событий между потоками.
24. **Остановка accept.** Event сообщает о завершении, закрытие listening socket прерывает ожидание accept.
25. **Закрытие окна.** Нужно остановить сервер и не оставлять фоновые ресурсы.
26. **Заголовок 1 МБ.** Сервер ограничивает размер заголовков 8 КБ и отвечает 400.
27. **Request smuggling.** Несогласованная интерпретация границ HTTP-сообщения разными узлами.
28. **Content-Length + Transfer-Encoding.** Неоднозначность framing может привести к request smuggling; безопасная реализация должна отклонять конфликт.
29. **Path traversal.** Попытка выйти из каталога через `../`; путь нормализуется и проверяется относительно хранилища.
30. **Безопасный парсинг.** Нельзя полагаться на неограниченные буферы; нужны лимиты, проверка длины и корректная обработка ошибок.
